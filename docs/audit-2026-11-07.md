**Date:** 2026-11-07 · **Commit audited:** `4ee3759` (main) · **Scope:** the Astro site, the contact-form Worker, CI/Dependabot, the live deployment, and the practice's public footprint as it bears on the site.

## 1. How this was done, and what was verified

- Every source file was read (all pages, components, config, styles, the Worker, its tests, CI, Dependabot, headers).
- A fresh `npm run build`, `npm test`, and `npm audit` on both package trees were run locally: **8 pages built, 7 site tests pass, 0 vulnerabilities in either tree.** The Worker's own vitest suite is run by CI; it was not re-run here.
- The live site was probed with curl and a real browser at desktop (1024 px) and phone (375 px) widths, including the contact form and mobile menu.
- Four parallel specialist reviews were run; every claim that could be checked against the build output or the live site was checked, and the ones that were wrong were corrected or dropped.

## 2. Executive summary

The site is in good technical shape: static, fast, no client framework, strong security headers, a well-tested contact Worker, clean dependency trees, and honest copy with no testimonials or guarantees. Nothing here is on fire. The weight of the findings is on the **business side** (the homepage doesn't say who the practice is for, the booking CTA leads to a form with no expectations set, the niches that would bring referrals are buried) and on **compliance paperwork** (no website privacy policy, a 2020-dated Notice of Privacy Practices, an insurance statement that overgeneralises). The one real **silent-failure risk** is the contact pipeline: nothing alerts anyone if sends start failing, and a plausible browser-autofill edge case can make a real inquiry vanish behind a green success banner.

## 3. Security

Overall posture is good for a static site: CSP with `frame-ancestors 'none'`, HSTS, nosniff, Referrer-Policy, Permissions-Policy; secrets kept out of the repo; Turnstile verified server-side with action and hostname checks; header injection and rate limiting tested. The findings are hardening, not holes.

| Sev | Finding | Where | Why / fix |
|---|---|---|---|
| Medium | **Honeypot can be filled by browser autofill.** The trap is an off-screen input named `company`, labelled "Company", with `autocomplete="off"`, which Chrome and Safari ignore for address-profile fields. If a saved profile has an organisation, a real person can submit, get the green "sent" banner (the Worker answers 200 and sends nothing) and never hear back. Not reproduced in a browser here, but the mechanism is widely reported and the fix is cheap. | `src/components/ContactForm.astro:204-207`, `workers/contact-form/src/index.js:78` | Rename to something no heuristic matches (e.g. `name="leave_blank"`, no autocomplete token), and in the Worker send honeypot hits anyway with a `[possible bot]` subject prefix (or at least count them in a `console.warn`) so a false positive costs a glance, not a client. |
| Medium | **Public repo with no branch protection on `main`.** One collaborator today, but Dependabot and any future collaborator can push straight to the branch that auto-deploys production. | GitHub settings | Require the `site` and `worker` CI checks and a PR for `main`. |
| Medium | **GitHub Actions pinned by mutable major tag** (`actions/checkout@v7`, `actions/setup-node@v7`). A re-pointed tag runs attacker code with the repo token (the tj-actions incident, March 2025). | `.github/workflows/ci.yml` | Pin to full commit SHAs with a version comment; Dependabot's `github-actions` stream updates SHA pins. Add a `concurrency` block to cancel superseded runs. |
| Medium | **Workers Logs invocation logs retain request metadata** (URL, method, headers including `CF-Connecting-IP`) for every submission for several days. The code's own `console.*` calls are clean of form content. | `workers/contact-form/wrangler.toml` `[observability]` | Add `invocation_logs = false`; `console.warn` and `console.error` still land in Workers Logs. Low urgency: there is no user-rendered content to inject through. | `public/_headers` | Move the form script to a bundled `<script>` reading its data from `data-*` attributes; hash the JSON-LD via Astro's CSP support. |

Harmless since nobody is served on `www`. | `wrangler.toml` routes | Drop the `www` route or leave it with a comment; nothing to fix. |
